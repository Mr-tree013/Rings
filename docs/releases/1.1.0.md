# Rings 1.1.0 — the conversational release

**Released:** 2026-09-21 · **Reference environment:** Linux / WSL + Python 3.13 · **Migrations:**
`0001`–`0019`

Rings 1.1.0 makes the conversation the primary way to run the system. Everything the previous
release could do through `pw` is now something you can say — and every external effect still ends
in the same place it always did: an exact, immutable payload, a human approval, and one execution.

## What is new since 1.0.0

### Tree, as the primary interface

`uv run rings` is the everyday surface. A sentence becomes one of a closed set of typed local
operations, a deterministic runtime decides what is allowed and what needs your confirmation, and
the runtime — never the model — writes what happened.

- Tasks, calendar events, work sessions, weekly planning and the reminder inbox are all reachable
  by saying what you want.
- Terminal input is decoded strictly, structured model output is normalized and repaired at most
  once, and every recoverable failure is a sentence instead of a traceback.
- "你能做什么" is answered from the runtime's own capability metadata, so it cannot drift away from
  what the build actually does.

### Weekly recurring schedules

A class that happens every week is one durable rule — one weekday, a local start and end time, an
explicit IANA timezone — not a pile of events and not a scheduled job. Occurrences are derived on
demand, `calendar.list` shows them, and the deterministic planner treats them as busy time, so it
never proposes a plan block on top of a class.

### Mail: read, reply, and now compose

- Read and search stored mail, see a message or a thread.
- Reply drafts are written with the existing draft service and prepared as an immutable
  `mail.send` action.
- **New outbound mail**: write a new letter to an address you typed, to a recorded contact, or to
  yourself. The model writes the words; the runtime decides who may be written to, and it accepts
  an address only if you wrote it yourself.
- **Contacts**: `张老师邮箱是 zhang@example.edu，记成联系人` records a local name → address pair that
  later mails can use by name.
- Every send — reply or new — shows the **exact** `From`, `To`, `Subject`, `Message-ID` and body
  from the approved action, and only your own explicit phrase (`确认发送`) sends it. `可以` never
  does. An ambiguous or unknown recipient is a question, never a guess.

### Confirmed long-term facts

`记住我的办公室在仙林` proposes a fact; the runtime shows the exact value and the sentence it came
from, and nothing is stored until you say `确认记住`. A passing statement is not a memory, a
generic `可以` does not confirm anything, and the final confirmation never touches the model.
`你记得我的办公室在哪里吗？` is answered from confirmed rows only — or with an honest "I have not
confirmed that".

### Today Brief

`我今天有什么事？` returns one deterministic summary of your own day in your configured timezone:
today's events, weekly classes and planned blocks, overdue and due-soon tasks, reminders, mail that
asks for a reply, what is waiting for your confirmation, and any external outcome that is still
unknown. It is a read: nothing is approved, sent or executed, and no summary is stored.

## Compatibility

- Migrations `0001`–`0019` apply forward-only to a 1.0.0 runtime; no data is rewritten.
- The `pw` command surface, the mobile control plane, MCP resources and the daemon are unchanged in
  shape: the conversation is a new front end over the same services.
- `v1.0.0` remains a published snapshot; `v1.1.0` is an addition, not a replacement.

## Known limitations

- **Attachments** are not supported in any mail flow.
- **One recipient per new letter**: no `Cc`, no `Bcc`, no multi-recipient compose.
- **No scheduled or delayed mail**, and no automatic sending of any kind.
- **No contact import or sync**: contacts are typed locally, one at a time.
- **Recurrence is weekly only**: no odd/even weeks, no every-N-weeks, no monthly or yearly rules, no
  holiday or exam-week exceptions.
- **Confirmed facts do not fill anything automatically**: no mail recipient, no mail body, no form,
  no external action reads a fact.
- **Conversational eHall is unavailable**: the certificate pipeline stays an explicit `pw` approval
  flow.
- **No voice interface and no web chat**: the surfaces are the terminal, the trusted-LAN mobile
  page (view/approve only) and the local MCP server (read-only unless explicitly enabled).
- **MCP remains bounded and local**: four read resources, two read tools and two optional task
  tools; no arbitrary tool loop.
- **Linux / WSL is the reference runtime.** The project is developed and tested there.

## Guarantees that did not change

- **exactly-once external effects, on demand**: one approved `ActionRequest` produces at most one
  `ExecutionRun`, and an outcome that cannot be proven is reported as unknown rather than retried.
- **Nothing external is autonomous**: mail and eHall both need a human approval bound to an exact
  payload fingerprint, and the conversation can only prepare.
- **The mobile control plane is a trusted LAN surface only**, and it is view/approve: it never
  executes an action.
- **MCP stays a bounded, local, non-executing surface**: read resources and task-only writes.

## Verification

- The full test suite passes with `TZ=UTC CI=true GITHUB_ACTIONS=true` and without it.
- `ruff`, `mypy`, `uv lock --check`, `git diff --check` and `uv build` are clean.
- The built wheel and sdist are installed outside the checkout and exercise `pw`, `assistantd`,
- `growing-assistant-mcp` and `rings`.
- Nothing in this release runs an external effect without an explicit human confirmation, and no
  conversation can create an approval, an execution or an eHall submission.
