## Phase 11C — Mail account settings (in progress)

Already done and committed (`6ff3135`):

- `docs/adr/0043-mail-account-settings.md` (Accepted).
- `src/assistant/adapters/config/mail_overlay.py`: the managed overlay, atomic and private writes,

- `tests/unit/test_mail_overlay.py`: 16 tests covering atomicity, permissions, round-tripping,
  credential smuggling, unmanaged keys, precedence, order and the untouched primary file.

Audited facts to build on, so they do not have to be re-derived:

- Credentials are environment-only today: `adapters/mail/credentials.py` derives
  `GROWING_ASSISTANT_MAIL_<ACCOUNT_ID>_PASSWORD` and `..._SMTP_PASSWORD`. There is no writable
  secret store, so ADR-0043 item 15 applies: store a secret reference only, and report
  "credentials configured = false" until the environment provides the value.
- Account metadata lives in `[[mail.accounts]]` in `config.toml`. `domain/config.py`
  (MailAccountConfig, _parse_mail_account, _KNOWN_MAIL_ACCOUNT_KEYS) already rejects
  password/secret/api_key keys.
- The loader is `bootstrap.config_loader(path) -> TomlConfigLoader`
  (`adapters/config/toml_config.py`); `AppPaths.resolve().config` is the XDG config root.
- The integrity check and the backup manifest already exclude credentials.
- **Where the connection probes may live.** `tests/unit/test_architecture.py` allows `imaplib` and
  `ssl` anywhere under `adapters/mail/`, but pins `smtplib` to `adapters/mail/smtp.py` alone. So the
  SMTP probe belongs *inside* `adapters/mail/smtp.py` (next to the delivery adapter, sharing its TLS
  policy) rather than in a new module, and the IMAP probe may live in a new
  `adapters/mail/connection_test.py`. Extending the `smtplib` pin to a second module would weaken a
  safety boundary for no benefit.

  `tests/integration/test_daemon_{scheduler,mobile,mail_worker}.py`; a new supervised service has to
  be added to each.
- The frozen web route set is in `tests/release/test_capability_surface_freeze.py`; a new route must
  be added there deliberately.
- `tests/unit/test_conversation_domain.py` pins the exact operation vocabulary. A new operation must
  be added there and to `_ARGUMENT_KEYS` in `domain/conversation_plan.py`. A missing entry shows up
  as a KeyError, which the runtime renders as 内部错误, not as an import failure.
- Modules under `application/` may not contain `datetime.now(`; the Clock rule is enforced
  textually. Pass a pre-computed value into a renderer instead.
- `pyproject.toml` has a per-file RUF001 ignore list for modules that answer in Chinese with
  full-width punctuation. A new such module has to be added there.
- Full-suite wall time on this host is dominated by per-test SQLite setup (roughly three seconds per
  test), not by the code under test, so a slow run is not by itself a regression.
